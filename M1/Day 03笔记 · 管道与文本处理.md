# Day 3 · 管道与文本处理：从小白到"从日志里揪出攻击者"

先别急着背命令。今天你只需要记住一个画面：

> **每个 Unix 工具都是一台只会干一件事的小机器。管道 `|` 是把它们串联起来的传送带。**
> 你的工作不是"背命令",而是**在脑子里想清楚:数据长什么样 → 我要把它变成什么样 → 中间需要几台机器。**

我们用一个贯穿全天的故事来学:**"半夜告警,有人暴力破解我们服务器,帮我查出是哪些 IP 干的。"**

---

## 第 0 站：先建立"数据流"的心智模型

一条命令运行时,内核给它打开 3 个"插槽"(术语叫**文件描述符**,fd):

| 编号 | 名字 | 默认插着谁 |
|---|---|---|
| 0 | stdin 标准输入 | 键盘 |
| 1 | stdout 标准输出 | 屏幕 |
| 2 | stderr 标准错误 | 屏幕(也是屏幕,但是另一条线) |

为什么 stdout 和 stderr 要分开?因为**正常结果**和**报错信息**是两种东西。你想把结果存文件,但不一定想把报错也塞进去。这个区分今天会反复用到。

`ls` 正常列出文件 → 走 **1**;`ls /不存在的目录` 报错 → 走 **2**。屏幕上看起来一样,其实走的是两条不同的管道。

---

## 第 1 站:重定向 —— 把插槽拔下来插到别处

### `>` 到底做了什么

```bash
echo hello > /tmp/a.txt
```

翻译成人话:**把 1 号插槽拔下来,插到文件 `/tmp/a.txt` 上**,然后再运行 `echo`。于是 `echo` 往 1 号插槽写的东西,就流进了文件。

- `>` 是 `1>` 的简写。
- `>` 会**清空**文件再写;想追加用 `>>`。
- 注意:`>` 打开文件这个动作,是在命令运行**之前**就完成的。这一点是下面所有坑的根源。

### `2>&1` 到底做了什么

```bash
2>&1
```

逐字符读:

- `2>` :把 2 号插槽拔下来
- `&1` :插到"**1 号插槽此刻插着的那个东西**"上(`&` 表示"1 是个插槽号,不是文件名叫 1")

⚠️ 新手最经典的错:写成 `2>1`(少了 `&`)。那不是"重定向到 1 号插槽",而是**创建一个名叫 `1` 的文件**。

### 面试高频坑:顺序决定命运

关键在于 `2>&1` 里的"**此刻**"。它是**复制当前状态**,不是"永远跟随 1 号"。

**写法 A(正确):**

```bash
cmd > /tmp/out.txt 2>&1
```

按顺序执行:

1. `> /tmp/out.txt`:1 号插槽 → 文件
2. `2>&1`:2 号插槽 → 复制 1 号现在插的东西 → 文件

结果:**正常输出和错误都进文件。**

**写法 B(经典错误):**

```bash
cmd 2>&1 > /tmp/out.txt
```

按顺序执行:

1. `2>&1`:2 号插槽 → 复制 1 号**现在**插的东西 → **屏幕**(因为 `>` 还没执行!)
2. `> /tmp/out.txt`:1 号插槽 → 文件

结果:**错误打到屏幕,正常输出进文件。** 2 号插槽早在第 1 步就被"焊死"在屏幕上了,后面 1 号怎么变都跟它没关系。

**一句话记住:**

> `2>&1` 必须写在 `>` **后面**。因为 `2>&1` 是"抄作业",你得先让 1 号把答案写好,2 号才能抄到。

### 亲手验证(1 分钟,务必做)

```bash
# A:都对
ls /不存在的目录 > /tmp/out.txt 2>&1
cat /tmp/out.txt          # 看到报错信息 → 说明错误也进文件了

# B:顺序反了
ls /不存在的目录 2>&1 > /tmp/out.txt
# 屏幕直接打印报错;再看文件:
cat /tmp/out.txt          # 空文件 → 说明正常输出才进文件
```

跑一遍,这个坑你这辈子不会忘。

## 第 2 站:管道 —— 只传 stdout 的传送带

```bash
命令A | 命令B
```

意思是:**把 A 的 1 号插槽,直接接到 B 的 0 号插槽上**。A 往屏幕写的东西,变成 B 从键盘读的东西。

**致命细节:管道只接 1 号插槽。2 号(stderr)会直接漏到屏幕,不进管道。**

```bash
ls /不存在的目录 | wc -l
# 屏幕:ls: cannot access ...   ← 错误漏到屏幕了
# 屏幕:0                        ← 管道里啥也没有,wc 数到 0 行
```

想让错误也进管道:

```bash
ls /不存在的目录 2>&1 | wc -l     # 输出 1
```

或者 bash 4+ 的简写:

```bash
ls /不存在的目录 |& wc -l
```

(注意 `|&` 等价于 `2>&1 |`,顺序天然是对的,所以它没有那个坑。)

## 第 3 站:文本处理小机器,一次只学"最小可用"

别一次背全。每个工具你只需要知道:**它吃什么 → 吐什么 → 什么时候用它。**

### `cut` —— 按"列"切

```bash
cut -d: -f7 /etc/passwd
```

- `-d:` 用冒号当分隔符(`-d` delimiter)
- `-f7` 取第 7 列(field)

`/etc/passwd` 每行长这样:`root:x:0:0:root:/root:/bin/bash`,第 7 列就是登录 shell。

> ⚠️ `cut` 只认**单个字符**分隔符,而且不会像 awk 那样"多个空格算一个"。所以遇到空格对齐的日志,用 awk 更省心。

### `sort` / `uniq` —— 排序与去重(必须成对出现)

```bash
sort /tmp/names.txt          # 字典序排序
sort -n                      # 按数值排(否则 10 会排在 9 前面!)
sort -rn                     # 数值 + 倒序(排行榜必备)
sort -k2                    # 按第 2 列排
```

`uniq` 有一个**反直觉的脾气**:

> **它只合并"相邻的"重复行。**

所以正确姿势永远是 `sort | uniq`,先把相同的行排到一起。

```bash
sort | uniq        # 去重
sort | uniq -c     # 去重并计数(c = count)
sort -u            # 去重 + 排序,一步到位
```

**`sort -u` 和 `sort | uniq` 的区别:**

| | `sort -u` | `sort \| uniq` |
|---|---|---|
| 结果 | 去重后的排序结果 | 去重后的排序结果(一样) |
| 能计数吗 | ❌ | ✅ `uniq -c` |
| 速度 | 略快(内部优化) | 稍慢,但功能多 |

结论:**要计数就用 `sort | uniq -c`;单纯去重 `sort -u` 更简洁。**

### `grep` —— 按"行"筛

```bash
grep "Failed password" /var/log/auth.log   # 含这个串的行
grep -c "error" file.log                   # 只要数量
grep -r "error" /var/log                   # 递归目录
grep -l "error" *.log                      # 只输出文件名(l = list)
grep -v "DEBUG" file.log                   # 反选:不要含 DEBUG 的行
grep -oE 'from [0-9.]+' file.log           # 只输出匹配到的片段(-o)
```

`-o` + `-E`(扩展正则)是捞日志的神器,后面会用到。

### `awk` —— 按"字段"处理,今天的主武器

先建立模型,别背语法:

```bash
awk 'BEGIN{开局}  条件{动作}  END{收尾}' 文件
```

- **逐行**读文件,每读一行,就把 `{动作}` 执行一次
- `BEGIN` 在处理第一行之前跑一次,`END` 在最后一行之后跑一次
- 行里的字段:`$0` = 整行,`$1` = 第 1 个字段,`$2` = 第 2 个……`$NF` = 最后一个
- `NF` = 这一行有几个字段;`NR` = 当前是第几行
- `-F:` 指定分隔符(默认是"空白",且**多个连续空格算一个**,这点比 cut 好用)

**最小可用三连:**

```bash
awk '{print $1}' file            # 打印每行第 1 列
awk '{print $NF}' file           # 打印每行最后一列
awk -F: '{print $7}' /etc/passwd # 用冒号分隔,打印第 7 列
```

**加上计算:**

```bash
awk '{s+=$1} END{print s}' nums.txt
```

这是啥?——**把每一行的第 1 列加到变量 `s` 上,所有行处理完后打印 `s`。也就是"求第 1 列所有数字之和"。**(awk 里没赋初值的变量默认是 0,所以不用先 `s=0`。)

**加上筛选:**

```bash
awk '$6 == 200 {print $3}' access.log    # 只处理状态码为 200 的行,打印 IP
```

这就是 awk 比 cut 强的地方:cut 只能切,awk 能**切 + 判断 + 计算 + 输出**。

### `sed` —— 按"行"编辑,最常用的只有两个模式

```bash
sed -n '1,5p' file.log        # 只看第 1~5 行(-n 抑制默认打印,p 是 print)
sed -n '/error/p' file.log    # 只看含 error 的行(等价于 grep error)
sed 's/old/new/' file.log     # 每行第一个 old 换成 new
sed 's/old/new/g' file.log    # 全部替换(g = global)
sed -i 's/old/new/g' file     # 直接改文件(-i,小心!)
```

小白记住:`sed -n 'Np'` 看指定行,`sed 's///g'` 做替换。够用了。

### `xargs` —— 把"一行行文本"变成"命令参数"

这是很多人卡住的地方。先看问题:

```bash
echo "a.txt b.txt"
```

`grep` 之类能直接吃 stdin,但 `ls`、`rm`、`basename` **只吃命令行参数**,不吃 stdin。`xargs` 就是翻译官:**把 stdin 的内容拼到命令后面当参数**。

```bash
grep -rl "error" /var/log 2>/dev/null | xargs -r ls -lh
```

拆开看:
- `grep -rl "error" /var/log`:递归找含 error 的文件,只输出**文件名**
- 后面接 `| xargs -r ls -lh`:把这些文件名当作 `ls -lh` 的参数
- `-r`:输入为空时**不要**执行后面的命令(否则 `ls -lh` 不带参数会列出当前目录,很危险)

再看带占位符的:

```bash
find /etc -name "*.conf" | xargs -I{} basename {}
```

- `-I{}`:用 `{}` 作为占位符,把每一行**单独**替换进去
- 效果:对每个找到的文件跑一次 `basename`

**xargs 最大的坑:文件名里有空格。**

```bash
find . -name "*.log" -print0 | xargs -0 rm    # 正确:用 \0 分隔
```

`-print0` 用空字符分隔,`-0` 按空字符解析,空格就不会把文件名劈开。**涉及"删除/移动"时一定加上。**

## 第 4 站:实战 —— 一条完整的流水线

现在你有零件了。真正的工作方式是:**先看清楚数据长什么样,再一段一段接。**

### 4.1 造 1000 行假日志

```bash
seq 1 1000 | awk '{print "2026-11-11 10:00:"($1%60)" 192.168.1."int($1%255)" GET /api/v1/item/"$1" 200 "$1}' > /tmp/fake.log
```

不想手打也可以存成脚本。生成后的每行长这样:

```
2026-11-11 10:00:01 192.168.1.1 GET /api/v1/item/1 200 1
```

**先别急着统计,先看格式:**

```bash
head -3 /tmp/fake.log
awk 'NR==1{print "NF =", NF}' /tmp/fake.log
```

对照数一下字段:

| $1 | $2 | $3 | $4 | $5 | $6 | $7 |
|---|---|---|---|---|---|---|
| 日期 | 时间 | IP | 方法 | URL | 状态码 | 字节数 |

> **这一步是今天最重要的习惯。** 网上抄来的 `$(NF-3)` 之所以经常错,就是因为没先看格式。

### 4.2 统计状态码分布

想清楚:我要按 `$6` 分组计数。

```bash
awk '{print $6}' /tmp/fake.log | sort | uniq -c | sort -rn
```

一段一段读:

1. `awk '{print $6}'` → 每行只留下状态码,1000 行 `200`
2. `sort` → 把相同的排到一起(uniq 的前提)
3. `uniq -c` → 相邻合并并计数,输出 ` 1000 200`(注意前面有空格)
4. `sort -rn` → 按数量倒序,做成排行榜

**这条 `... | sort | uniq -c | sort -rn` 是你今天要背下来的唯一"模板"。** 90% 的"XX 排行榜"都是它。

### 4.3 统计每个 IP 的请求数(排行榜)

同样的模板,把 `$6` 换成 `$3`:

```bash
awk '{print $3}' /tmp/fake.log | sort | uniq -c | sort -rn | head
```

输出的样子:

```
     7  192.168.1.6
     7  192.168.1.5
     ...
```

### 4.4 统计 URL 出现次数 —— 顺便学个教训

```bash
awk '{print $5}' /tmp/fake.log | sort | uniq -c | sort -rn | head
```

结果会全是 `1`,因为每个 URL 都带唯一编号,天然不重复。

**这说明:统计之前必须想清楚"按什么聚合"。** 真实日志里你会按"路径前缀"聚合:

```bash
awk '{print $5}' /tmp/fake.log | sed 's|/[0-9]*$||' | sort | uniq -c | sort -rn | head
```

`sed 's|/[0-9]*$||'` 把结尾的 `/数字` 删掉,`/api/v1/item/1` 就变成了 `/api/v1/item`。

### 4.5 终极任务:攻击者 IP 排行榜

真实场景:`/var/log/auth.log`(Debian/Ubuntu)或 `/var/log/secure`(CentOS)里,SSH 暴力破解的行长这样:

```
Nov 11 03:12:45 web01 sshd[1234]: Failed password for invalid user admin from 192.168.1.5 port 54321 ssh2
Nov 11 03:12:47 web01 sshd[1235]: Failed password for root from 10.0.0.9 port 54322 ssh2
```

**第一步:一定先看格式**,别急着定列号:

```bash
sudo grep "Failed password" /var/log/auth.log | head -3
```

你会发现有两种行:`invalid user admin from ...` 和 `root from ...`。字段数不同!这就意味着 `$(NF-3)` 在某些行上会数错(第一种行 NF=16,`$(NF-3)` 是 IP;第二种行 NF=14,`$(NF-3)` 是 `from`)。

**所以更稳的写法是"找锚点",而不是"数位置":**

```bash
sudo grep "Failed password" /var/log/auth.log \
  | grep -oE 'from [0-9]+\.[0-9]+\.[0-9]+\.[0-9]+' \
  | awk '{print $2}' \
  | sort | uniq -c | sort -rn | head
```

逐段解释:

| 段落 | 作用 |
|---|---|
| `grep "Failed password"` | 只留失败登录的行 |
| `grep -oE 'from <IP>'` | **只输出匹配到的片段**,不管它在第几列 |
| `awk '{print $2}'` | 把 `from 1.2.3.4` 里的 IP 取出来 |
| `sort \| uniq -c` | 相同 IP 排一起并计数 |
| `sort -rn` | 数量倒序 |
| `head` | 只看前 10 名 |

这就是**"攻击者 IP 排行榜"**。而且这个方法不依赖日志格式的细节,换台机器也能用。

**如果想更专业一点,直接按"日期+小时+IP"分组,看攻击的时间分布:**

```bash
sudo grep "Failed password" /var/log/auth.log \
  | grep -oE '[A-Z][a-z]{2} [ 0-9][0-9] [0-9]{2}.*from [0-9.]+' \
  | awk '{print $1, $2, $3, $NF}' \
  | sort | uniq -c | sort -rn | head
```

(这个只是展示"流水线可以任意加长",看不懂可以先跳过。)

### 4.6 xargs 批量实战

```bash
# 找出所有含 error 的日志文件,列出它们的大小和权限
grep -rl "error" /var/log 2>/dev/null | xargs -r ls -lh

# 安全版:处理可能含空格的文件名
find /var/log -name "*.log" -print0 | xargs -0 ls -lh
```

注意 `2>/dev/null` 的作用:**把 grep 的"权限不够"报错丢进黑洞**,免得刷屏干扰结果。这是 `2>` 的实战用法。

## 第 5 站:自检 + 答案

先别看答案,自己说一遍。

### Q1:`cmd 2>&1 > out.txt` 的输出都去哪了?

**答:** 错误(stderr)去了**终端屏幕**,正常输出(stdout)去了 `out.txt`。

因为从左到右执行:先 `2>&1` 让 2 号抄 1 号,此时 1 号还指着屏幕,所以 2 号被焊死在屏幕;然后 `>` 才把 1 号改到文件。要"都进文件",必须写 `cmd > out.txt 2>&1`。

### Q2:`awk '{s+=$1} END{print s}'` 在算什么?

**答:** 把每一行的第 1 个字段**当作数字**累加到 `s`,所有行读完后打印总和。即"第 1 列求和"。

如果第 1 列不是数字(比如是 IP),awk 会把它当 0 加,结果是 0——这个"静默失败"也是常见坑。

### Q3:`sort -u` 和 `sort | uniq` 有什么区别?

**答:** 结果一样(去重后的有序列表),区别在能力:`uniq -c` 可以**计数**,`sort -u` 不能。另外 `uniq` 单独使用时只合并相邻重复行,所以必须先 `sort`。单纯去重用 `sort -u` 更简洁。

### Q4(附加):管道里的 stderr 去哪了?

**答:** 漏到屏幕上了。因为 `|` 只接 1 号插槽。要接进管道用 `2>&1 |` 或 `|&`。

## 附录:今天用到的命令速查

| 需求 | 命令 |
|---|---|
| 输出都进文件 | `cmd > f 2>&1` |
| 追加 | `cmd >> f 2>&1` |
| 错误也进管道 | `cmd 2>&1 \| next` 或 `cmd \|& next` |
| 丢弃报错 | `cmd 2>/dev/null` |
| 取某列 | `cut -d: -f7` / `awk -F: '{print $7}'` |
| 取最后列 | `awk '{print $NF}'` |
| 过滤行 | `grep 模式` / `grep -v 模式` |
| 只输出匹配片段 | `grep -oE '模式'` |
| 排序 | `sort` / `sort -n` / `sort -rn` |
| 去重计数 | `sort \| uniq -c \| sort -rn` |
| 求和 | `awk '{s+=$1} END{print s}'` |
| 批量执行 | `... \| xargs -r 命令` / `xargs -I{}` / `xargs -0` |

## 三句话带走今天

1. **`2>&1` 是"抄作业",必须写在 `>` 后面**,否则 2 号抄到的是还没改过的 1 号。
2. **排行榜模板只有一个**:`取出要统计的列 | sort | uniq -c | sort -rn`。
3. **动手前先 `head` 看格式,用"锚点"定位字段,不要迷信 `$(NF-3)`**——这一条能帮你省掉 80% 的调试时间。
